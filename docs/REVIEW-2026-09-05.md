# Review, end of day one

Everything built on 2026-09-05, judged as it stands, against the frame the
owner set that evening: **Kikoe is not a tool. It is an operating
environment for productive, creative people.** The daemon, the Room, the
board, the orb and the ear are the first pieces of that environment, built
for coding agents first because that is where the owner lives.

Status is real. Numbers below were measured on the author's machine.

## What is strong

- **The thesis survived the port intact.** Silence by default, one mouth for
  many agents, permission by voice, everything local. The narration evals
  transferred verbatim and pass; the register is code.
- **The permission loop is real end to end.** A hook holds open in `curl`,
  the question is spoken and drawn, a yes releases it with the decision
  Claude Code understands, and the same path serves the board's asks.
  Nothing here is mocked.
- **The Room is the product's face and it matches the design.** The board
  is a pannable, zoomable surface with cards the agent pins and the user
  arranges; the orb is the logo and the state at once; light and dark both
  hold; the window is ours down to the title bar.
- **The agent has a vocabulary.** Speak, show, ask; diff, markdown, table,
  image, page, SVG, diagram. The output style tells it when each earns its
  place. This is the seed of the OS: a surface other things push to.
- **The whole thing is one runtime.** No Python, no sidecar, one process
  tree, native modules that load inside Electron. Installers build.

## What is weak, ranked by how much it matters

1. **A day's work is uncommitted.** One bad `git` command loses it. Commit
   before anything else.
2. **The ear is unproven.** Every routing path was exercised with text; not
   one real utterance has gone through the microphone. Until it has, the
   listening half is a claim.
3. **Memory.** 777 MB is a lot for an ambient app that should disappear.
   The ear holds Whisper base at 284 MB whether or not anyone is talking;
   three renderer processes each cost ~100 MB. The OS ambition needs this
   to be a background presence, not a foreground weight.
4. **A race in the local voice.** sherpa's engines are not re-entrant. A
   preempt aborts a line by returning false on its *next* chunk, while the
   arbiter starts the next line on the same engine at once. The log's
   "TTS settlement failed" came from exactly this shape during the early
   restart-on-switch design. It will come back under preemption.
5. **Nothing persists.** History, pins, heard lines, positions on the board
   all vanish on relaunch. An environment remembers; a tool forgets.
6. **The second screen can approve.** Anyone holding the Room link can
   answer a permission from any device. Useful, and exactly one link away
   from a tool call approved by whoever found the link. There is no viewer
   token, no read-only mode, and the token rides in the URL.
7. **Renderers are untested.** 4.4k lines of plain JS with no tests, in
   the part users look at. The overlay bug (a `display: grid` beating
   `hidden`) sat unnoticed for hours and made the Room look nothing like
   its design; a screenshot test would have caught it in seconds.
8. **The install story lags the product.** Onboarding never mentions the
   Room, the board, or the ear. The Node fallback hook is written but has
   never run. The app CI workflow has never run. macOS has never run.
9. **The Python repo is still connected.** Twelve dead ClaudeTalks hooks
   sit in the owner's settings beside Kikoe's. The migrate button exists;
   nobody has pressed it.

## The frame: an operating environment, not a tool

What "OS for creative people" demands that a voice layer does not:

- **A surface others push to.** The board already is one, with `/show`.
  The next step is that things other than a coding agent can push: a
  design tool, a build, a calendar, a script, a phone. The contract is
  small and stable; make it public and versioned.
- **Persistence and place.** Projects, not sessions. Pins that survive a
  restart and belong to a project. A board per project; "switch to the
  storefront" moves the room. Positions remembered.
- **Memory of you.** The Companion tier in the old plan: tasks, notes,
  what was said, across days. Local. That is where "productivity" lives.
- **Creative, not only coding.** Adapters for the tools creative people
  already use: image and design work through MCP servers, writing, audio.
  The Room does not care what pinned the diff; it should not care what
  pinned the moodboard either.
- **Presence, not weight.** An environment is on all day. It must idle
  near nothing, wake in under a second, and never be the thing that made
  the machine slow.
- **Every screen in the house.** The Room on a monitor, the board on an
  iPad, a question on a phone, the voice in the room. Same daemon.

The trap is the same as the IDE trap: an OS is built one used surface at
a time, not by drawing the whole thing first. The Room is used. The next
surface earns its place by being used too.

## Enhancements, ranked

**This week, small, high return**

1. **Commit.** Then push, so the app workflow runs for the first time and
   the Mac question gets its first answer.
2. **Engine mutex.** One generation at a time per sherpa engine; a
   preempted line's abort is awaited before the next line starts. Removes
   the race for good.
3. **A real voice.** Ten utterances into the headset, watched in the
   Control Room's "what you said". Fix what they reveal: the name gate's
   alias list and the VAD's silence window are guesses until then.
4. **Screenshot tests.** The daemon already serves the Room to a browser;
   a headless Chrome in CI loads it with staged pins in dark and light
   and diffs against a stored image. The overlay bug never recurs.
5. **Lighter ear.** Whisper tiny English (a third of the memory, adequate
   for "yes", "no" and the control words) with base as the upgrade;
   unload the model after ten quiet minutes; reload on the first sound.
6. **A viewer token.** A second token that can read the stream and the
   board but cannot answer, speak, or clear. The tray copies the viewer
   link by default; the full link is one more click and a warning.

**This month, the environment**

7. **Persistence.** A small SQLite in the home: pins, positions, history,
   heard lines, per project. The board comes back the way it was left.
8. **Projects.** A project is a name, a set of repos, a voice, a board.
   "Switch to storefront" by voice or click moves the whole Room.
9. **Onboarding rewritten around the Room**: the first thing a person
   sees is the Room with a demo playing on the board, not a settings
   page.
10. **Renderer processes on a diet.** The settings window closes to
    nothing when hidden; the island stays; the Room is the only renderer
    that lives all day.
11. **The phone.** The Room's needs-you strip as a notification with allow
    and deny, through a tunnel the user owns.

**Next quarter, the OS**

12. **A public `/show` contract** with a version, examples for scripts,
    and adapters for two non-coding tools so the board proves it is not
    a coding thing.
13. **The Companion**, ported from the Python design: memory, proposals
    with a spoken yes, speaking first behind a governor.
14. **Signing, auto-update, ten strangers.** Unchanged from the app plan,
    and still the difference between a demo and a product.

## What I would not do

- Draw the whole OS on the canvas before the next surface is used.
- Add editing to the board. The moment it has a cursor, the room is a
  desk again.
- Bundle a model larger than the job. The environment is judged idle.
